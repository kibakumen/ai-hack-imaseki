## 入口

| 誰 | URL |
| --- | --- |
| 客 | `/me` |
| 店 | `/store?key=<店の鍵>` |
| 運営 | `/admin?key=unei2026`（環境変数 `ADMIN_KEY` を設定すればそちらが優先） |

店の鍵は `node scripts/seed.mjs` が `.store-keys.local`（git の対象外）に書く。種データの鍵は `scripts/seed.mjs` に平文で入っている（**デモ用。実運用の鍵ではない**）。

## v1 から変えたところ（v2 の新しい要件）

- **届け方が逆**: 店が送るのではなく、客が「今すぐ探す」を押した時に、その瞬間の条件で探す
- **店が複数**・店ごとの編集画面（住所・ホームページ・提供メニュー・オファー3つ）
- **オファーの単位が「何名×何組」**。受け取られるたびに残りが1減る
- **受付時間**（何時から何時まで）で出る・出ないが決まる。配信の波と上限は無い
- **提供メニューと嗜好のマッチング**: AI が上位10件のメニューと客の好みを見比べて最大5件を選び、理由を1文書く
- **8桁のクーポン番号**を受け取りのたびに発行。店が番号で使用済みにできる。食べログなどのクーポンは店が手で打つ
- **運営の管理画面**: 登録店の一覧・オファー公開中の店・提供メニュー・新規店の承認
- **人数に合わないオファーは消さずに非活性**で見せる

## この版の負債（本開発で直す）

- 店と運営の認証が URL の `?key=`。運営の鍵は未設定なら `unei2026` に落ちる
- 種データの店の鍵が `scripts/seed.mjs` に平文（public リポジトリに入る）
- 入力の検査が手書き（スキーマ検査ではない）。画面側は応答の形を検査していない
- 自動テストが無い。連打の抑止も無い
- 取得の応答が約10秒（AI の待ち時間を15秒に延ばしたため）。本開発の目標は8秒
- 客の本人確認が無い（識別子を知っていればその客として操作できる）
- 受け取りの側で、承認の取り消し・最終有効日・店の情報の欠落を見ていない（本開発の要件では参照で塞いだ）
